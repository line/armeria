# v1.41.0

## 🌟 New features

- **Server-Side xDS**: An Armeria server can now be configured by an xDS control plane using
  [XdsServerPlugin](type), which manages TLS certificates and HTTP filter decoration on the given
  ports. Virtual hosts, routes and services stay user-defined — xDS never takes over service
  dispatch. See the new [xDS documentation](/docs/advanced/xds/introduction).
  #6820 #6833 #6837
  ```java
  Server.builder()
        .plugin(XdsServerPlugin.of(xdsBootstrap, "listener_name", 8080)) // 👈👈👈
        .service("/api", myService)
        .build();
  ```
  - A `Listener`'s `filter_chains` and `default_filter_chain` are fully resolved, so TLS and
    routing can be configured per filter chain.
  - A connection is matched by destination port, SNI hostname, transport type and ALPN, and its
    certificate is selected by SNI — exact DNS SAN match, then wildcard, then the first.
- **Server Plugin**: Bundle server-level concerns — ports, TLS, decorators, listeners — into a
  reusable [ServerPlugin](type) registered with [ServerBuilder#plugin(ServerPlugin)](type). Plugins
  are re-installed on [Server#reconfigure(ServerConfigurator)](type) and closed on stop. #6825
  ```java
  public final class ObservabilityPlugin implements ServerPlugin {

      @Override
      public void install(ServerBuilder sb) { // 👈👈👈
          sb.decorator(MetricCollectingService.newDecorator(
                    MeterIdPrefixFunction.ofDefault("http.service")))
            .decorator(LoggingService.newDecorator())
            .service("/internal/healthcheck", HealthCheckService.of());
      }
  }
  ```
- **Per-Request Client TLS and SNI Override**: [ClientTlsProvider](type) resolves a
  [ClientTlsSpec](type) per request from the [ClientRequestContext](type), and the SNI hostname is
  now readable and overridable via [ClientRequestContext#setSniHostname(String)](type). #6855
  ```java
  ClientFactory.builder()
               .tlsProvider((ClientTlsProvider) ctx -> // 👈👈👈
                       ClientTlsSpec.builder()
                                    .trustedCertificates(certsFor(ctx.sniHostname()))
                                    .build())
               .build();
  ```
- **Independent TLS for CONNECT Proxies**:
  [ProxyConfig#connect(InetSocketAddress,ClientTlsSpec)](type) configures the proxy hop's TLS
  separately from the backend — a different trust store, proxy mTLS certificate or ALPN list. An
  unset ALPN list defaults to HTTP/1.1, since that is what CONNECT proxies speak. #6854
- **Connection-Aware Server TLS Provider**: [ServerTlsProvider](type) resolves a
  [ServerTlsSpec](type) from a [ConnectionContext](type), so a certificate can be chosen by ALPN,
  remote address or custom attributes rather than the SNI hostname alone. Returning `null` falls
  back to the virtual host's TLS settings. #6806
- **Circuit Breaker Alignment with `SuccessFunction`**:
  [CircuitBreakerRuleBuilder#onSuccessFunction()](type) and its
  [CircuitBreakerRuleWithContentBuilder#onSuccessFunction()](type) counterpart make a rule match
  when the client's [SuccessFunction](type) regards a response as a success. This also fixes a
  breaker that could never close because its trial requests kept matching `thenIgnore()`. #6828
  ```java
  CircuitBreakerRule rule =
      CircuitBreakerRule.builder()
                        .onSuccessFunction() // 👈👈👈
                        .thenSuccess()
                        .orElse(myRule);
  ```
- **Custom JSON Marshaller for Transcoding Proxies**:
  [DelegatingHttpJsonTranscodingServiceBuilder#jsonMarshallerFactory(Function)](type) lets a
  standalone HTTP/JSON transcoding proxy use a custom [GrpcJsonMarshaller](type), for example to
  render proto3 fields that hold their default value. #6826
- **HTTP QUERY Method**: Armeria now supports `QUERY` from
  [RFC 10008](https://www.rfc-editor.org/info/rfc10008/), a safe, idempotent method that carries a
  request body. [WebClient](type), [BlockingWebClient](type) and [RestClient](type) can send it, and
  a server handles it with [@Query](type) or
  [AbstractHttpService#doQuery(ServiceRequestContext,HttpRequest)](type). #6861
  ```java
  WebClient client = WebClient.of("https://example.com");
  HttpResponse res = client.query("/search", "q=armeria"); // 👈👈👈 the body carries the query

  // On an annotated service
  @Query("/search") // 👈👈👈
  public HttpResponse search(HttpRequest req) { ... }
  ```
- **Athenz xDS Filters**: The new `xds-athenz` module lets an xDS control plane drive Athenz
  authentication and authorization — an outbound filter injects access tokens, and an inbound
  filter authorizes requests against Athenz policies with configurable action/resource mapping. #6853
- **Envoy Fault Injection**: The `envoy.filters.http.fault` filter is now supported, injecting abort
  responses and delays into the request path on both the client and the server side, optionally only
  when request headers match. #6888
- **Weighted Clusters**: `weighted_clusters` in a `RouteAction` splits traffic across backend
  clusters by weight — say 90% stable, 10% canary. Each target still honors its own
  `typed_per_filter_config` and `metadata_match`. #6836

## 📈 Improvements

- A failure to bind a port at startup is now wrapped in [ServerPortBindException](type), whose
  [ServerPortBindException#serverPort()](type) reports exactly which [ServerPort](type) failed, so
  probing ports before starting the server is no longer necessary. The original transport exception
  is kept as the cause, and non-bind startup failures are propagated unchanged. #6819
  ```java
  if (Exceptions.peel(e) instanceof ServerPortBindException bindEx) {
      ServerPort port = bindEx.serverPort(); // 👈👈👈 which port failed, and why
  }
  ```
- [TlsKeyPair](type) now validates that the private key matches the leaf certificate's public key at
  construction time, so a mismatch fails fast. #6892
- [ClientRequestContext#setClientTlsSpec(ClientTlsSpec)](type) now switches the
  [SessionProtocol](type) to its TLS variant, and the new
  [ClientRequestContext#clearClientTlsSpec()](type) switches it back to cleartext. A decorator can
  therefore turn TLS on or off for an individual request. #6895
- [ZtsBaseClient](type) is now an interface, so you can supply your own [WebClient](type) — for
  example one built from an xDS cluster snapshot. JWKS keys are fetched with that same
  [WebClient](type), honoring its TLS and proxy configuration, instead of a separate
  `SSLContext`. #6848
- **xDS** — the following improve xDS clients and custom extensions:
  - A cluster's `HttpProtocolOptions` is now honored, so a cluster that explicitly declares HTTP/1
    or HTTP/2 gets the matching [SessionProtocol](type) instead of defaulting to `HTTP`/`HTTPS`. #6843
  - Load balancer selection is observable through the `armeria.xds.lb.request` and
    `armeria.xds.lb.request.subset` counters, tagged with cluster, priority, locality and
    `result=hit`/`result=miss`. #6840
  - A custom cluster type can be plugged in by registering an [XdsExtensionFactoryProvider](type)
    that supplies a [ClusterTypeFactory](type), then naming it in the Cluster's
    `cluster_type`. #6811 #6838
  - `RetryBackOff` accepts an `exponential_backoff_factor`, so the retry multiplier is no longer
    fixed at Envoy's 2x. This is an Armeria-specific extension, absent from upstream Envoy. #6874
  - A custom config source only needs to return a [SnapshotStream](type) of `DiscoveryResponse` from
    [SotwConfigSourceSubscriptionFactory](type); Armeria handles parsing, storage and
    notification. #6795
  - An `HttpFilter` with `disabled: true` is now skipped, and RPC (Thrift) clients honor the xDS
    `RetryPolicy`, which was previously ignored silently. #6864
  - [XdsPreprocessor#whenReady()](type) waits for the first snapshot, so a client does not race the
    initial configuration fetch. #6838
  - Custom protobuf packages can be registered for [XdsResourceReader](type) via the
    [XdsTypeRegistryPackageProvider](type) SPI, and `custom_config_source` also resolves by name. #6838
  - [SnapshotStream#caching(Function)](type) deduplicates keyed subscriptions by reference counting,
    so external modules no longer need to fork the internal implementation. #6831

## 🛠️ Bug fixes

- Closing a [DnsAddressEndpointGroup](type) now releases the UDP socket held by its underlying DNS
  resolver. Previously every group leaked one socket for the lifetime of the process. #6846
- A request that arrives during the brief window of [Server#reconfigure(ServerConfigurator)](type) is
  now served normally by [AuthService](type), instead of failing with a `NullPointerException` and
  `500 Internal Server Error`. #6832
- An authority that combines a long hostname with a port no longer throws
  `IllegalArgumentException: The label in the input is too long`. IDN normalization is now applied to
  the parsed hostname rather than to the whole authority. #6859 #6860
- A certificate with neither a common name nor a subject alternative name — typically a root CA found
  in a trust store — now exports `tls.certificate.*` metrics tagged with its subject DN instead of an
  empty `hostname`. #6862
- [AttributesSetters#getAndSet(AttributeKey,T)](type) no longer throws a `ClassCastException` when
  the attribute had been set to `null` to hide a value inherited from a parent. It is now declared
  `@Nullable` and returns `null` in that case instead of an internal sentinel. #6889
- A failure to obtain an Athenz token now surfaces its original cause, such as
  [UnprocessedRequestException](type), instead of a `NullPointerException` or a misleading
  [AccessDeniedException](type). Only a `403 Forbidden` from ZTS is wrapped now, so code that caught
  [AccessDeniedException](type) for a `401` or `400` sees the original exception instead. #6866
- Three xDS defects are fixed: server-side filter chain matching now rejects a connection whose
  protocol does not match the matched filter chain's TLS configuration; locality-aware routing now
  honors the configured locality weights, which were previously scaled by 100 and so produced
  skewed distributions; and a watcher no longer receives a spurious [MissingXdsResourceException](type)
  when a cached resource already exists at registration time. #6887

## 📃 Documentation

- The xDS module is now documented on the site, covering concepts, bootstrap configuration, client
  and server usage, extensions, metrics and supported features. #6724
  - [xDS introduction](/docs/advanced/xds/introduction)

## 🏚️ Deprecations

- [ZtsBaseClient#ztsUri()](type) and [ZtsBaseClient#proxyUri()](type) are deprecated because they
  leak implementation details. Use [ZtsBaseClient#webClient()](type) and read the URI from it
  instead. #6848

## ☢️ Breaking changes

- The SNI hostname is now precomputed when the [Endpoint](type) is set, not derived from the
  authority at connection time. A decorator that rewrites the authority or `Host` header no longer
  changes it — call [ClientRequestContext#setSniHostname(String)](type) instead. #6855
- `ProxyConfig.connect(addr, true)` now gives the proxy hop a default [ClientTlsSpec](type) with
  system defaults instead of reusing the client factory's TLS configuration. Pass an explicit spec
  to [ProxyConfig#connect(InetSocketAddress,ClientTlsSpec)](type) to restore the old behavior. #6854
- [ClientRequestContext#setClientTlsSpec(ClientTlsSpec)](type) now switches the
  [SessionProtocol](type) to its TLS variant; call [ClientRequestContext#clearClientTlsSpec()](type)
  for cleartext. [RequestOptions#clientTlsSpec()](type) is a default and does not switch it. #6895
- The `:ai:mcp` module builds against MCP Java SDK 2.x. [ArmeriaStatelessServerTransport](type) and
  [ArmeriaStreamableServerTransportProvider](type) keep their API, but you must move your MCP SDK
  dependency to 2.0.0, which renames `ElicitRequest` to `ElicitFormRequest`. #6889
- **xDS** — the following affect custom extensions and control-plane configuration:
  - User decorators now run **before** xDS filters (`user decorators → xDS → transport`). A
    decorator that relied on seeing xDS-injected headers must move into an xDS filter. #6890
  - A `Cluster` of type EDS must set `eds_cluster_config`; the inline `load_assignment` fallback is
    gone. #6811
  - Unsupported fields are rejected rather than warned about, and there is no warn-only mode. #6864
  - [XdsHttpFilter](type) drops `httpPreprocessor()`/`rpcPreprocessor()` — implement
    `httpDecorator()`/`rpcDecorator()` instead. #6864
  - A single [XdsExtensionFactoryProvider](type) SPI replaces the [HttpFilterFactory](type),
    [SotwConfigSourceSubscriptionFactory](type) and [ClusterTypeFactory](type) registrations; move
    your `META-INF/services` entry to it. Built-ins are no longer SPI-overridable — register custom
    factories with [XdsBootstrapBuilder](type)`.extensionFactories()`. #6820 #6838
  - [SotwConfigSourceSubscriptionFactory](type)`.create()` returns a [SnapshotStream](type) of
    `DiscoveryResponse`; `ResourceWatcher`, `XdsStreamSubscriber`, `ConfigSourceSubscription` and
    `SotwSubscriptionCallbacks` are removed. #6795
